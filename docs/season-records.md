# 연도별 투구 기록 · 2024–2026

투구 기록과 공의 궤적은 연도별로 조회합니다. 영상과 영상에서 추정한 메커니즘은 기존 2024년 자료를 사용합니다.

| 연도 | 공개 투구 수 | 경기 수 | 기록 범위 |
|---|---:|---:|---|
| 2024 | 215,691 | 708 | 2024-03-23–2024-10-01 |
| 2025 | 215,788 | 714 | 2025-03-22–2025-10-04 |
| 2026 | 153,820 | 499 | 2026-03-28–2026-08-04 |

합계 585,299구이며, 세 연도를 통틀어 투수 449명이 포함됩니다. **2026년은 확보한 원본의 마지막 경기인 8월 4일까지입니다. 이후 경기는 포함하지 않았습니다.** 네이버 중계 API에서 추가 수집을 시도했으나 연결 시간이 초과되어, 그 이후 기록의 확보를 확인하지 못했습니다. 확보한 기록의 범위를 시즌 전체 경기 수로 표현하지 않습니다.

## 출처와 기존 기록

원본은 [where-do-the-robot-umpires-see](https://github.com/leekichang/where-do-the-robot-umpires-see/tree/37cf62be0604aa8a7f077759eebf7a6eda002edb/data)의 연도별 CSV입니다. 2026-08-10 커밋을 고정하고 파일 SHA256과 Git blob을 [pts_sources.json](../scripts/pts_sources.json)에 기록했습니다. 2024년 원본 215,525구, 2025년 215,788구, 2026년 153,820구를 가져왔습니다.

기존 동작 수집 경기의 11,161구 중 원본 CSV에 없는 166구도 2024년 기록으로 보존했습니다. 중복 여부는 전체 경기 ID와 투구 ID로 확인하며, 기존 투구 ID·투수 코드·경기가 일치할 때만 원래 동작 연결과 지표를 유지합니다. 새 기록에 같은 투수의 다른 영상이나 다른 연도의 동작을 연결하지 않습니다.

원본에 없는 투구 전 카운트·누적 투구 수·타석 ID·초/말 정보는 만들지 않습니다. 구속·위치·기록된 결과와 구종은 원본에서 가져옵니다. 영상 및 생체역학 파일은 다시 계산하거나 수정하지 않았습니다.

## 궤적과 저장 정밀도

HB·IVB·VAA는 기존 [PTS 궤적 계산식](pitch-flight.md)을 사용합니다. 원본 궤적이 유효하지 않으면 값을 채우지 않습니다. 기존 기록의 궤적 누락 7구도 누락 상태로 남깁니다.

홈페이지에서는 기록을 16개 압축 묶음으로 나눠 필요한 연도와 투수만 불러옵니다. 투구 데이터의 HB·IVB는 0.001cm, VAA는 0.001°, 위치는 0.0001ft 단위로 저장합니다. 이는 저장 정밀도이며 실제 관측 정확도를 뜻하지 않습니다. 전체 원본 계수는 연도별 원본 CSV에서 확인할 수 있습니다.

- [seasons/manifest.json](../data/seasons/manifest.json): 연도별 범위·원본·투수 목록·열 정의·파일 해시.
- `data/seasons/{연도}/profiles.json.gz`: 투수별 구종·구속·표본 집계.
- `data/seasons/{연도}/bucket-00.json.gz`부터 `bucket-15.json.gz`: 투구별 기록. 원본 투구 ID와 경기 목록 인덱스로 전체 ID를 복원합니다.
- 데이터 탐색의 CSV/JSON 다운로드: 현재 선택한 연도의 필터를 통과한 전체 투구입니다. 화면에 표시된 행이나 점으로 다운로드 범위를 제한하지 않습니다. 순수 궤적 JSON은 `columns`와 행 배열 `rows`를 제공합니다.

큰 데이터의 차트는 실제 투구를 일정 간격으로 골라 최대 2,000점을 표시하며, 전체 유효 표본 수를 표시합니다. 집계와 다운로드에는 모든 투구를 사용합니다.

## 화면과 공유 링크

선수 페이지의 기록 연도 선택은 구종 비율·구속·HB·IVB·VAA에 적용됩니다. 대표 투구폼, 메커니즘 카드와 키네마틱 시퀀스에는 2024년을 표시합니다. 선택한 구종의 2024년 영상이 없으면 짧은 안내를 표시합니다. 새 투수의 과거 영상을 추측해서 붙이지 않습니다. 원본에서 소속팀을 확인할 수 없는 연도에는 2024년 소속팀을 현재 팀처럼 표시하지 않습니다.

```
/?pitcher=65320&season=2026#pitchers
/?db_family=flight&db_season=2025&db_player=65320#database
/#visuals/affinity?v=arsenal1&year=2026&player=54640&s=30
```

연도가 없는 일반 기록 화면은 최신 확보 연도인 2026년부터 보여줍니다. 기존 고급 메커니즘·동작 연결 링크는 2024년 범위에서 유지합니다. 기존 `arsenal1` 유사도 링크에 연도가 없으면 원래의 2024년 비교를 유지합니다. 유사도 계산에 서로 다른 시즌을 섞지 않습니다.

## 재생성

```sh
python scripts/build_season_records.py \
  --source 2024=/path/to/2024.csv \
  --source 2025=/path/to/2025.csv \
  --source 2026=/path/to/2026.csv
```

Python과 NumPy가 필요합니다. 기존 `data/portal/players` 및 `pitch_flight.json`에서 보존할 2024년 기록을 읽습니다. 현재 영상 목록이나 기존 지표 데이터베이스는 덮어쓰지 않습니다. 원본이 바뀌면 소스 해시와 자료 범위를 먼저 확인해야 합니다.

## 네이버 API 추가 수집

`scripts/collect_naver_pts.py`는 일별 경기 목록과 `/schedule/games/{gameId}/game-polling?inning={번호}`를 요청합니다. 기존 수집 코드의 실제 요청 경로를 확인했으며, `/relay`로 대체하지 않습니다.

```sh
python scripts/collect_naver_pts.py \
  --from-date 2026-08-05 --to-date 2026-10-30 \
  --output /path/to/private/pts-2026
```

수집 결과는 홈페이지에 자동 반영하지 않습니다. 원본 JSON을 압축 저장하고, 투구 ID로 중계 이벤트와 궤적을 연결한 `pitches.jsonl.gz` 및 수집 보고서를 남깁니다. 성공한 요청은 재실행 때 재사용합니다. 경기 종료와 마지막 이닝을 확인한 경기만 완료로 기록하며, 응답 실패를 경기 없음으로 처리하지 않습니다. 3일 연속 실패하면 중단합니다.

2026-10-30 점검에서는 이 서버와 별도 GitHub 실행 환경에서 경기 목록·`game-polling` 모두 응답 시간이 초과되었습니다. 네이버 중계 페이지도 API 자료를 불러오지 못했습니다. 이후 기록은 아직 미수집이며, API가 응답하면 수집 보고서·투구 식별·새 원본 해시를 확인하고 연도별 데이터를 다시 생성해야 합니다.
