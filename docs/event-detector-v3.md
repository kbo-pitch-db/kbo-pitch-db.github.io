# 투구 이벤트 탐지 v3 · 2026-10-29

릴리스는 실제 공 탐지와 궤적으로, 착지는 신발·지면 영상 특징으로 추정하도록 바꿨습니다. 손목 속도 피크를 릴리스로 대체하지 않습니다. 813개 전체에 두 영상 모델을 실행했습니다. 몸 자세만으로 이벤트를 추정하던 이전 공개본과 구분합니다.

## 바뀐 계산

공 탐지에는 [BaseballCV의 ball_trackingv4](https://github.com/BaseballCV/BaseballCV)를 사용했습니다. 여러 관측 이미지에서 검출한 공을 짧고 매끄러운 궤적으로 연결하고, 그 궤적이 투수의 손에서 멀어지는지 확인합니다. 손목은 이 투수가 던진 공인지 연결하는 데만 쓰며, 손목 속도의 최대 시점을 릴리스로 쓰지 않습니다. 궤적이 불연속하거나 서로 경쟁하는 후보가 있거나 장면이 전환되면 결과를 보류합니다. 원본 관측 간격보다 정밀한 시점을 만들지 않습니다.

착지는 좌우 발 라벨이 바뀌어도 같아지는 신발 두 개와 주변 지면의 영상 특징을 사용합니다. [DINOv2 ViT-S/14](https://github.com/facebookresearch/dinov2)의 고정된 특징 위에 작은 접촉 분류기를 학습했습니다. 접촉 이전과 이후 상태의 변화를 연속 이미지에서 찾아 첫 접촉 구간을 추정합니다. 기존에 원본을 검토한 18개 착지 구간을 학습에 사용했습니다. 같은 원본 영상이 학습과 평가에 동시에 들어가지 않도록 원본 영상 단위 교차 평가도 수행했습니다. 이 개발 평가에서는 착지 분류기를 따로 평가하기 위해 검토한 릴리스 구간을 입력했고, 착지 차이 중앙값은 약 71ms였습니다. 아래 새 표본 비교는 공 탐지부터 실행한 전체 결과입니다. 소규모 잠정 라벨을 사용한 모델이며, 힘판으로 정의한 접촉 검출기가 아닙니다.

카메라의 배경 움직임과 신발 위치를 추적한 진단도 보존합니다. 좌우 발 라벨의 전환을 시간적 연속성으로 연결하며 3D에서 고정한 발 위치를 정답으로 쓰지 않습니다. 착지 영상 특징은 두 신발의 순서에 영향을 받지 않도록 합칩니다. 2D·3D 자세 파일 자체를 변경하지 않습니다.

## 새 표본 비교

전체 데이터에서 미리 고정한 순서의 첫 12개 새 클립을 검토했습니다. 모델·탐지 규칙을 고정한 뒤, 탐지 결과를 표시하지 않은 원본 프레임에서 구간을 표시했습니다. 착지가 그래픽에 가려진 두 개는 착지 정답을 비워뒀습니다. 이 표본은 **클립이 겹치지 않는 비교**이며, 개발 영상과 같은 원본 영상이 일부 포함됩니다. 검토자는 코딩 에이전트이고 독립된 사람의 정답은 아닙니다. 전체 813개의 정확도를 입증하는 표본으로 해석하면 안 됩니다.

| 이벤트 | 비교할 구간 | 기존 후보 검출 | 새 후보 검출 | 기존 중간 시점 차이 중앙값 | 새 중간 시점 차이 중앙값 | 기존 90백분위 | 새 90백분위 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 착지 | 10개 | 8개 | 8개 | 75ms | 75ms | 260ms | 170ms |
| 릴리스 | 12개 | 7개 | 10개 | 100ms | 42ms | 147ms | 132ms |

위 중앙값은 **각 방식에서 검출된 항목만** 계산한 값이므로 누락 수도 함께 표시했습니다. 두 방식 모두 후보를 검출한 같은 6개 클립만 비교하면 릴리스 차이 중앙값은 100ms에서 25ms로 줄었습니다. 착지는 같은 6개에서 약 75ms로 거의 같았습니다. 착지의 큰 오차는 줄었지만 중앙값이 개선됐다고 주장하지 않습니다. 새로운 방식에서도 잘못된 후보가 남습니다.

## 화면과 집계

영상에서 검토한 이벤트, 자동 후보, 확인할 수 없는 이벤트를 구분합니다. 이벤트 버튼에 표시한 구간을 누르면 2D·3D가 해당 프레임으로 함께 이동합니다. 무릎 최고점이 없더라도 착지와 릴리스가 확인되면 두 시점으로 비교할 수 있습니다. 이때 왼쪽 구간은 ‘착지 전’이며 무릎 최고점으로 표시하지 않습니다. 앞 구간은 착지→릴리스 구간과 같은 길이로 봅니다.

공 궤적과 영상 접촉 상태가 사전에 고정한 조건을 만족한 자동 결과는 이벤트에 맞춘 **미리보기**로 볼 수 있습니다. 자동 후보는 선수 대표값 집계에 넣지 않습니다. 원본을 검토한 이벤트만 대표값 후보로 사용하고, 관측 구간 경계와 이벤트·필터 민감도 검사를 거칩니다. 같은 구종·자세에서 기록과 연결된 서로 다른 투구가 3개 이상이어야 대표 중앙값을 표시합니다. 이벤트가 불명확한 경우 곡선을 없애지 않고 클립 시간으로 확인할 수 있게 합니다.

일반 재생속도 가정은 유지합니다. 30fps의 한 프레임은 약 33ms이며 실제 중복 이미지는 시간 정밀도를 높여주지 않습니다. 이벤트 오차와 단안 3D 분절 방향·관절각 오차는 별개입니다. 이벤트를 개선했다고 3D 각도나 회전속도가 실측 정확도를 갖게 되는 것은 아닙니다.

## 데이터와 재현

- [`events_v3.json`](../data/kinematics/events_v3.json), `.json.gz`: 813개 영상의 검토 이벤트, 자동 후보, 공 궤적 근거와 접촉 분류 결과.
- [`event_validation_v3.json`](../data/kinematics/event_validation_v3.json): 클립별 비교, 누락 수, 고정한 규칙·모델 해시와 출처.
- [`source_event_reviews_v3.json`](../data/kinematics/source_event_reviews_v3.json): 새 12개 영상의 잠정 검토 구간.
- [`foot_contact_linear.json`](../data/kinematics/models/foot_contact_linear.json): 이번에 학습한 접촉 분류기. 사전학습된 공 탐지·DINOv2 가중치는 재배포하지 않습니다.

공 탐지 모델은 공식 BaseballCV 다운로드 주소에서 받은 `ball_trackingv4`이며, DINOv2 코드 리비전은 `e1277af2ba9496fbadf7aec6eba56e8d882d1e35`입니다. 실제 가중치 SHA-256은 검증 JSON에 있습니다. 기존 자세 환경과 분리한 `.events-env`에서 `ultralytics==8.3.40`, `scikit-learn==1.3.2`, PyTorch 2.1.2+cu118로 계산했습니다.

`infer_event_ball.py`, `infer_event_foot_features.py`는 로컬 원본 영상과 기존 자세/관측 시각을 읽고 숫자 특징을 개인 연구 폴더에 저장합니다. `train_event_contact.py`는 개발 검토 구간만 사용하며, 이번 공개본은 배포한 고정 분류기 가중치를 사용합니다. `build_pitch_event_candidates.py --workers 6`, `publish_pitch_events.py`, `build_kinematic_sequence.py` 순서로 공개 숫자 데이터를 생성합니다. 방송 이미지는 배포하지 않습니다. 원본·모델의 사용 조건은 각 출처를 따릅니다.
